# Mower 排班编辑器

编辑器根据一图流的[页面编写文档](https://ark.yituliu.cn/docs/writing-page)在现有路由 `/tools/mower-plan` 更新，不增加路由或修改导航结构。

最近一次排班差异核对至 2026-10-16 的 alpha 提交 `5e2782d29`。已包含多绑组空列独立轮休、设施等级及副表心情条件，本次补齐 `4f3f331ee` 的贸易订单校验：主表配置一、二岗位的贸易站只能使用赤金订单（龙门商法），主表或任意副表配置合成玉订单（开采协力）均报错。判断沿用主表岗位数，开启自动切换、单独修改设施等级或在副表增加岗位不能绕过；三岗位贸易站仍可在开启自动切换后切换订单。校验只提示修正，不改写保存的订单或驻员。

近期 `80685b976` 将用尽协调作为独立前置安排，防止附带普通恢复或空闲填床占用目标组所需床位；确认协调驻员后再根据实读占用重算替班和床位，未来用尽任务不提前预留。`52c0329e5` 修正制造站加速预留：有跑单站且启用自定义预留时从 MAX 减去预留量，例如库存 250、预留 20 时使用 230；低于库存门槛仍跳过，无跑单站或 `not_customize` 通过门槛后仍全部使用。`1342a9f32` 修复跑单确认时机及回收站收取记录。这些变化由 Mower 本体执行，不增加排班文件字段；本次不替换一图流收益演算引擎，也不在浏览器静态校验中推断运行结果。排班 JPG 格式在本次核对范围内没有新增变化，继续使用现有 14 码导出及 14/16 码导入。

同步基准为 ArkMowers/arknights-mower 的 `alpha` 前端及回收站适配分支，源码提交 `d3eab6202e316fc1356ac654c3fe535e4a8a64f8`。复用其绑组、名单增减、设施换位、触发表达式和心情设置控件；上游代码采用 [MIT 许可](./LICENSE.mower)，Copyright (c) 2021 Nano。

排班静态校验与图片格式另同步至 alpha 提交 `e4a460d58e7acd64969674cd9da2412d66df62ee`：全零心情工作绑组不要求普通工作主班；普通绑组需要能决定上下班的固定主班。候补不计入必需恢复床位，用尽与回满要求仍优先。显式 Free 只增加所属绑组的有效床位，固定宿舍替班优先保留必需恢复成员。

零心情替班规则同步至 Mower 提交 `ea7846c9b22955ec72d13330ec2bdd39b39bd0a4`：未绑组的零心情工作主班，以及当前绑定全部成员均配置零心情工作的工作主班，可省略普通替班；多绑组按每列判断，混合组仍要求每位成员填写替班。已填写的普通替班保留名称、主班身份和唯一匹配检查，菲亚梅塔仍需填写有效主班充能对象。宿舍成员不获得工作替班豁免，实测心情为零也不获得豁免。副表按合并后的名单增减重新判断。

同组主班互填与床位计算同步至 Mower 提交 `043fee6a`：同一非空组内不同主班可互填替班，不限设施。动态床位需求根据完整唯一匹配计算，只计未被选作替班的必需恢复主班；工作替班继续工作，固定宿舍替班使用对应恢复位置。同一候选只能抵扣一次，候补、零心情工作、用尽与回满规则继续生效；床位不足时优先匹配能减少必需动态床位的主班，真实缺床仍报错。主表与每张副表分别按生效配置检查。

工作替班占用修复对应 [Mower PR](https://github.com/ArkMowers/arknights-mower/pull/1384) 的提交 `6b137cf2`。工作替班占用由 Mower 运行时检查：成员正在为其他组接工作替班时，本组整组暂缓下班，即使该成员原岗位的替班名单兼容。实读占用和同轮已选工作安排均保留岗位，已排队任务在执行前重新检查；占用岗位显式交接后才能释放成员。例如自动化下班后乌尔比安、安哲拉分别替清流、温蒂工作，深海须等待这两个岗位释放。浏览器只检查静态配置，不预测实际换班时序；收益计算源代码镜像保持原有范围。

多绑组空列规则同步至 [Mower 提交](https://github.com/ALEXsun0/arknights-mower/commit/8221615b238e391fb4e73d7c8302f518eb201a27)：每位多绑组干员可填写一列空绑组，首列和附加列均可，重复空列仍报错。工作主班通过空列替班按自身心情独立轮休；具名组休息时优先使用这些组共同可用的替班，空列不参与交集，已经休息的干员继续恢复。宿舍候补仍可为更高优先级主班让床。主副表保存和导入导出保留空列及其替班；空列仍受普通替班校验约束，不能充当具名组的计时主班，也不出现在绑组心情条件的组名候选中。换班时序由支持该规则的 Mower 执行，浏览器收益计算源代码镜像不随本次编辑器同步更新。

宿舍隔离与维护副表帮助同步至 Mower 提交 `3de2b2ac6`、`19a322969`：入住前优先减少同组同住，可交换普通位住客，并让新入住者由单回位改住普通位；隔离结果相同时仍按恢复优先级分配单回位。维护副表的跑单主班配置其他跑单替班时，先用替班加速一轮并恢复原班，再切入维护主班；没有此类替班时直接切入。以上安排由 Mower 运行时执行，编辑器保留对应配置与说明。组内恢复时间差阈值、额外等待上限、宿舍低优位顺序及副表顺序覆盖已支持，导入导出继续保留这些设置。

浏览器每次校验复用岗位绑定索引，全零心情工作组只匹配已填写的普通候选；副表合并只创建覆盖设施和岗位数组，检查过程只读共享岗位，减少整表深拷贝。浏览器仍逐一检查主表和每张副表单独生效的配置，Mower 的副表组合结果复用由后端执行。

设施等级与电力摘要同步至 Mower 提交 `c2cd17883`。顶层 `facility_levels` 保存主副表共享的手动等级，控制中枢与宿舍可设 0–5 级，其他设施可设 0–3 级；0 表示未建造。选中设施后在类别左侧编辑等级，“恢复默认”仅删除该设施的手动值。未设置的会客室、加工站、办公室、训练室和回收站默认 3 级，包括未配置干员的设施；其他设施继续按主表布局和两电站、三电站规则推断，默认值不表示来自游戏观测。电力摘要使用实际建造等级，回收站不耗电，加工站建造后固定耗电 10。等级修改不会删除原有岗位；缺电、未建造却配置驻员、超出等级容量由摘要和静态校验提示。副表不能抬高手动等级或增加主表没有的左侧岗位，右侧新增岗位仍受等级容量限制。JSON、云端保存与图片继续携带该映射；这些设置只描述设施，不会改变游戏内等级。等级、容量和电量由独立的 `utils/mower/facility_levels.js` 处理，不依赖收益演算模块。

`store/planStore.js` 负责浏览器排班编辑和文件转换，`store/configStore.js` 负责随排班携带的高级设置。设施位置、设施内编辑器和换班设置顺序保留 Mower 原版布局，文件工具栏置于外围。干员头像及库存物品图标使用一图流的既有雪碧图，生产物品图片与收益计算共用 `utils/mower/productAssets.js`。`utils/mower/plan_qr.js` 复用收益计算的 Base45/zlib 编解码，并提供 alpha 14 码导出及旧版 16 码导入兼容；收益计算页也使用相同图片解码入口，不改动其源代码镜像。云端排班继续使用既有 `buildingApi`。办公室、训练室和回收站的显示顺序仅保存在浏览器，不随排班导出。

图片导出为质量 95% 的 JPG，携带完整主副表及高级设置。上下各 7 个二维码位于左侧生产设施的空白区，按实际设施边界计算位置和大小，避免遮挡设施、干员和右侧回收站；只截取设施图，不包含设施编辑表单。亮暗主题均可导入，二维码按几何行排序，兼容旧图和加高、整体平移后的图片。WebKit 导出前预渲染一次，以加载嵌入图片资源。

Vuetify 的 `useTheme()` 只在页面 `setup` 中调用一次，计算属性读取其响应式主题状态。主表设置通过引用对象直接编辑，副表设置直接编辑对应副表，不用相互写入的监听器同步设置。

副表选择框在选择或排序后保持展开，点击外部或按 Esc 关闭。任务使用横向干员标签并在右侧排列，添加干员按钮紧随标签，设施选择框固定为 160px，行级加减按钮固定在右侧。

“校验排班”在浏览器中检查主表及每张副表单独覆盖主表后的配置，包括干员名称与重复主班、替班、绑组、宿舍 Free 顺序、设施和任务容量、产物切换开关与心情上下限。它不判断副表组合的可达性、运行状态或干员持有情况，实际使用前仍需在 Mower 中完整校验。

运行 `npm run check:mower-plan` 检查旧文件兼容、主副表设置往返、多绑组、回收站容量、设施布局隔离、生产设施换位、干员替换和浏览器静态校验。`npm run check:mower-plan-images` 检查图片布局、新旧二维码往返、亮暗主题及残缺图片拒绝。设施等级的独立定向检查使用 `node scripts/check-mower-facility-levels.mjs`，覆盖默认与手动等级、容量、电力、主副表边界及导入导出。生产构建使用 `npm run build`。

选择干员时，悬停下拉选项可查看各阶段基建技能、效果和解锁条件；已选字段与标签不显示提示。技能数据复用一图流已有的基建技能表。

文件工具栏的“转到 收益计算（Mower）”将当前编辑的完整主表、副表和高级设置带入收益计算页，无需先导出文件。跳转前使用收益页的现有解析器确认排班可载入；解析或浏览器保存失败时保留编辑页，收益页原有排班也不会被覆盖。

副表条件中的“绑组心情”可选择主表与全部副表的非空组名，包含多绑组附加列，重复组名只显示一次。只改产物或高级设置的空副表也可选择主表的绑组；切换编辑表或更新候选名单不改写已保存的条件表达式。这里收集组名供条件编辑，不计算心情；Mower 运行时的最低、最高绑组心情仍排除多绑组干员。
