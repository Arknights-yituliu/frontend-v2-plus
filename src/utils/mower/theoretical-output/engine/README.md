# Mower 收益计算引擎

本目录是 [R.I.I.C-Calculator](https://github.com/Panda-Panta/R.I.I.C-Calculator) 的浏览器计算快照。源提交与逐文件 SHA-256 记录在 `source-manifest.json`；文本统一先将 CRLF 换行为 LF，再以 UTF-8 编码计算哈希，避免 Windows Git 换行转换造成跨平台误报。保留 `THIRD_PARTY_MOWER_LICENSE` 的 Mower MIT 声明。只包含收益模拟、Mower 导入/二维码、报表所需依赖；不包含原应用外壳、自动排班优化器或候选组合目录。

当前快照固定为云端已提交版本 `8885cdcc5a6d6f57a1c961a7af6fc8ebea2f892b`，99 个文件的全部源哈希来自该提交，不包含源工作树未提交修改。`operatorHelpers.ts` 和 `inventoryAdmission.ts` 仅提取运行时所需成员，函数体未改写。

导入适配记录在清单中：

- `workbench/compat/mowerJson.ts` 仅在导入前清空默认岗位，确保进驻干员来自排班文件。缺失设施及无实际驻舍干员、仅有 Free 或空位的宿舍按原算法视为未建造，以等级 0、空岗位表示；等级推断不会自动补建。未建造设施不计耗电、技能、产出或休息床位。`workbench/validate.ts` 现与源文件一致。

外层 `../calculate.ts` 负责网站数据适配与计算参数：默认预热 3 天、采样 7 天、整小时暖机、最大步长 0.25 小时、种子 -1（每次计算通过浏览器 `crypto.getRandomValues` 生成随机 uint32）、理想跑单、无限材料、不使用无人机。结果显示并导出实际种子；适配器接受显式非负整数种子用于复现，测试对照使用固定 42，页面不固定种子。调度沿用最新主程序默认的 `mower-default`；引擎包含完整预演及异常重试模块，但网站不额外启用实验 `mower-alpha`。仍按实际心情事件执行轮班、菲亚交换、订单与无人机任务。理想订单不占用排班操作时间，也不影响普通换班唤醒；调度使用独立心情阈值事件，并确认具体 Free 宿舍人员的实际恢复顺序。原算法仅支持理想跑单，已移除 Grandet 跑单模式及其专用调度模块。完整成功采样才返回日均产出；换班延后尚未全部确认恢复时保留原诊断、导出延后记录，并在页面明确提示不能据此确认长期稳定产出。未完成、执行失败或含无效数值的报告仍拒绝显示收益。

使用一图流干员库时，主班、替补、菲亚目标及副表岗位、任务、条件所引用干员必须持有；只用于策略排序、标记或排除的名单校验名称，但不要求持有。每个技能槽只使用实际精英阶段和等级已解锁的版本。实际库优先于孑精 0 覆盖。快照尚未收录但未被排班引用的新干员会被明确提示并排除空闲候选。未启用干员库则采用原算法的最高技能与全目录空闲池，并在报告说明。

`mowerReportMetrics.ts` 保持原报表口径：经验、赤金价值、订单龙门币、虚拟赤金及 82 综合值为日均；订单数量和分布为整个采样窗口的计数。新增 `scoreBreakdown` 按各数值成员校验，默认权重仍为经验 1、赤金 0.8、订单 0.2；虚拟赤金不进入物理库存。报告保留原算法关于积分、设备时钟、未量化技能与被跳过副表条件的诊断。

验证命令：

```sh
node scripts/check-mower-theoretical-output.mjs
node scripts/check-mower-theoretical-output.mjs --source /absolute/path/to/R.I.I.C-Calculator
```

第一条会校验全部移植文本的规范化哈希及集成边界。第二条还校验全部源文件规范化哈希，并直接读取原仓库已存在的公开 252/342 排班夹具，在相同参数下逐字段比较原报表结果；夹具不复制到本仓库。验证的是移植后算法一致性，不是游戏实测或完整 Mower 设备行为证明。
